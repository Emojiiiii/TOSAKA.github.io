## 开发时间线

### 2026.10.08｜网站基础搭建与视觉设计

**开发目标**

建立网站的基础结构，确定整体视觉方向，并实现桌面端与移动端的基本适配。

**实现过程**

**1. 网站基础架构**

- 使用 HTML、CSS 和 JavaScript 搭建网站。
- 通过 GitHub Pages 部署，使网站能够公开访问。
- 规划 Home、Portfolio、Journal、About 和 Contact 等主要模块。
- 将页面样式与结构分离，为后续添加功能和维护代码做准备。

**2. 视觉风格设计**

网站主要面向游戏行业相关岗位，因此我希望在视觉上保留一定的游戏科技感，但又不让复杂的装饰影响作品本身的展示。

最终选择以深色背景、简洁排版和较大留白为基础，通过背景图、字体层级及页面动画增加视觉表现力。

**3. 响应式背景设计**

首页最初采用单张背景图片，但在测试中发现，适合电脑横屏的图片并不一定适合手机竖屏。

为了解决这一问题，开始采用根据屏幕比例切换不同背景图片的方案，使桌面端与移动端能够分别使用更适合的构图。

**4. 页面交互设计**

为了避免作品集变成普通的长页面滚动展示，尝试引入页面切换动画与视差效果，让不同内容区块之间的过渡更加自然。

同时重新考虑 Contact 模块的交互方式：相比将联系方式直接放在页面底部，我更倾向于让访问者通过导航栏主动打开联系方式，使主要浏览流程集中在作品与个人介绍上。

**遇到的问题与解决思路**

开发过程中发现，桌面端与移动端不仅存在屏幕尺寸差异，在滚动行为和触摸交互上也有所不同。

例如，移动端测试中曾出现页面打开后自动跳转到下方区域的问题，需要进一步检查页面初始化、滚动位置与动画逻辑之间的关系。

**阶段成果**

完成网站的基础页面结构、初步视觉风格、背景适配方案，以及页面切换交互的基础开发。

**开发反思**

在这个阶段，我逐渐认识到，作品集网站的设计不能只追求视觉效果。

对于作品展示平台而言，动画、排版和交互都应该服务于内容本身。任何可能干扰用户浏览作品的效果，都需要重新评估其必要性。

### 2026.10.08｜Journal 内容管理系统搭建

**开发目标**

建立一个可以长期维护的文章系统，用于发布设计过程、项目总结及技术开发记录，而不需要每新增一篇文章就手动制作独立 HTML 页面。

**实现过程**

**1. 引入内容管理系统**

- 将 Pages CMS 与 GitHub 仓库连接。
- 使用 Markdown 作为文章内容格式。
- 配置 `.pages.yml`，定义文章管理方式及媒体文件路径。
- 建立 Journal 文章存储目录。

**2. 实现动态文章列表**

最初完成 CMS 配置后，文章虽然能够生成独立页面，但 Journal 首页不能自动显示新的文章。

因此进一步完善文章列表的读取与生成逻辑，使新发布的内容能够出现在 Journal 首页。

**3. 处理文章访问问题**

在测试过程中，还遇到了文章已经发布但无法正常显示，以及部分页面返回 404 的情况。

通过检查文章存储位置、发布状态、访问路径与生成文件之间的关系，逐步调整系统配置。

最终完成文章列表和文章详情页的访问测试，并清理部分不再需要的文件。

**遇到的问题与解决思路**

这次开发中最大的挑战不是文章页面本身的视觉设计，而是理解内容、路径和页面生成机制之间的关系。

之前的网站主要依靠手动编写页面，而 CMS 的加入让内容管理与页面布局逐渐分离。

这种结构使后续发布内容更加方便，同时也减少了重复修改 HTML 的需求。

**阶段成果**

完成 Journal 的基本内容管理与文章发布流程，可以通过 CMS 创建文章，并通过网站访问相应的内容。

**开发反思**

相比单纯增加页面，建立可复用的内容管理机制更有长期价值。

这次开发让我开始更多地关注网站的可维护性，而不只是某一个功能能否实现。

### 2026.10.09｜统一视觉规范与 Portfolio 详情页开发

**开发目标**

改善网站不同页面之间的视觉一致性，同时为 Portfolio 的作品卡片增加独立详情页，让未来的游戏设计项目能够拥有更完整的展示空间。

**实现过程**

**1. 统一字体和导航设计**

在测试中发现，不同页面的字体风格、字号以及顶部导航栏的尺寸存在差异。

因此对现有页面进行了视觉规范调整，使它们在字体和导航布局方面尽可能保持统一。

**2. 实现 Portfolio 详情页**

- 为首页三个 Portfolio 作品卡片增加点击打开功能。
- 复用此前 Journal 已经实现的文章详情页结构。
- 调整 Portfolio 详情页导航，使其与 Journal 保持一致。
- 对页面打开及导航功能进行测试。

**3. 考虑后续内容扩展**

与 Journal 主要展示图文内容不同，Portfolio 需要展示游戏项目中的多种素材，例如武器设计图、不同角度的展示图片、动画视频，以及部分技术实现内容。

因此，后续需要对作品编辑与媒体展示结构进行扩展，而不只是简单复用文章正文。

**遇到的问题与解决思路**

最初可以为 Portfolio 重新制作一套独立的详情页系统，但这样会增加重复代码，后续修改导航、排版或交互时，也可能需要同时维护多套结构。

因此，我优先选择复用已经完成的 Journal 功能，再针对 Portfolio 的特殊内容需求逐步扩展。

这种方式有助于降低开发和维护成本，也更符合整个网站长期迭代的需求。
