# Background

Most computer networks allow two-way communication. For example, when you load a webpage, your browser requests the page, then the website’s server responds with the data needed to render the webpage. Two-way networks are the norm due to their flexibility, but there are security benefits to only allowing one-way communication. For example, a safety-critical network within a nuclear power plant should not have two-way communication with the Internet, to prevent hackers from interfering with operations. However, a one-way connection only allowing data to leave the plant would allow remote monitoring, while defending against cyberattacks.

Network devices which physically enforce one-way communication are known as data diodes. Commercially available data diodes are very expensive (prices can exceed $100,000), so our lab is developing lower-cost options (costing less than $100). The underlying hardware is simple, and can be constructed using fiber-optic network equipment. As shown below, the Ethernet media converter on the left sends data to the media converter on the right. The converter on the right physically cannot transfer data in the reverse direction, since its transmit port is taped over.

The challenge is sending data reliably. When data is sent over a network, the data is transmitted as a sequence of packets. Is is common for packets to be lost in transit (i.e., dropped). Packet loss is manageable on two-way networks: the receiver can simply request retransmission of any missing packets. However, this isn’t possible when using a one-way network, since the receiver cannot communicate with the sender. When using one-way networks, packet loss must be minimized and mitigated.
